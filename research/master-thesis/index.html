Master Thesis: Overcoming the Markovian Bottleneck - Efficient Memory Integration for Lightweight VLAs

Motivation

With the recent progress of AI models in perception, world understanding, reasoning and planning, there has been a huge shift in robotics towards integrating these capabilities into robot policies (the models that decide what a robot does next). The goal is to enable robots to perceive and understand complex, dynamic environments and autonomously perform tasks within them, unlike traditional robots (e.g., industrial robots), which typically operate in static, predictable environments.

An important approach in this field are Vision-Language-Action models (VLAs), such as OpenVLA1, which fine-tune a vision-language model to output low-level robot actions such as joint movements. These large, transformer-based models take an instruction for the robot (e.g., “clean the kitchen”) and combine it with the current camera images to predict the next low-level actions, such as moving forward or bending an arm down.

Deploying learned robot policies in complex, dynamic environments such as shop floors or people’s homes requires robots to keep a form of temporal memory, i.e., remember what they have done or seen previously. Most existing VLAs, however, only process the current observation, i.e., a single frame. They are therefore “Markovian”: they act as if the current frame contains everything relevant, and have no memory of the past. Simply giving them past frames is not feasible: more frames mean more input tokens and slower inference, which is a problem for large, multi-billion-parameter models on robots that have to act in real time.

In my thesis, I therefore look at memory for small VLAs (<1B parameters): can they become memory-aware through fine-tuning alone, and what is the best way to feed past observations into the model?

Example Imagine a robot is instructed to press a button three times. After a press, the button looks identical whether it has been pressed once, twice or twenty times. A policy that only sees the current frame cannot tell how many more times it needs to press the button. It is therefore crucial to integrate some form of memory into robot policies.

Related Works

To mitigate this single-frame limitation, researchers have started proposing approaches to integrate memory in the form of past observations into VLAs. Existing approaches roughly fall into two groups. Explicit methods let the model keep a running summary of the past, for example a short text description of what has happened so far (MEM). They need extra training labels, which are costly to produce. Implicit methods instead feed past camera frames to the model directly, e.g. by storing compressed features of earlier frames in a memory bank the model can read from (MemoryVLA), or by compressing past frames inside the VLM (ContextVLA). These need no extra labels, but often rely on large-scale training from scratch or on special inputs such as depth.

In contrast, I focus on standard, small VLAs that only use RGB images and no extra labels, and adapt an existing pretrained model instead of training one from scratch.

Approach

I start from the X-VLA model (see Figure 1, left), a small single-frame VLA that consists of two parts: a vision-language model that understands the scene and a smaller “action expert” that outputs the movements. I extend this model with a memory module which compresses past camera frames into a single memory token. This token is then used to steer the action expert via Adaptive Layer Normalization (AdaLN). In this model, which I call AdaMem, the memory is not added as an additional input, but rather works as a conditioning signal (see Figure 1, center). As an alternative, I implement a second variant, Concat, where the encoded past frames are directly concatenated to the input of the action expert (see Figure 1, right).

In both variants, I add the memory after the VLM and only into the action expert. The reason is that many VLMs used for VLAs are pretrained on single frames only and therefore provide no temporal understanding. Feeding them past frames would shift them away from what they were trained on and make them much more expensive to run. So instead, the VLM only sees the current frame and stays frozen, which lets me keep its pretrained knowledge. Only the rest of the model, including the new memory module, is fine-tuned. The trade-off is that the VLM cannot help to interpret the past frames. In return, AdaMem processes each frame only once and caches its features, so the VLM runs once per step, no matter how long the history is.

Figure 1: From left to right: The X-VLA baseline integrates only the current observation. X-VLA-AdaMem conditions the action expert on past encoded observations via an AdaLN-stream, while X-VLA-Concat simply concatenates encoded past observations to the input sequence of the action expert.

Results

I train and evaluate my models on LIBERO-Mem, a benchmark that extends LIBERO with tasks that specifically require memory, such as picking up a bowl 5 times. I measure the success rate on 8 of its tasks, giving the memory-based models a history of the 12 most recent frames.

AdaMem clearly outperforms both the memory-unaware X-VLA and the Concat variant on all 8 tasks. Compared to X-VLA, the average success rate across all tasks increases from 13.5% to 73% (see Figure 2).

Figure 2: X-VLA-AdaMem clearly outperforms the memory-less X-VLA baseline and the naive concatenation approach.

X-VLA-Concat reaches only 46.5% with the same history, so it clearly falls behind. A likely reason is that appending past frames makes the input of the action expert much longer and different from what it saw during pretraining (see Figure 1, right). To make use of it, the action expert has to relearn how it attends to its input, which costs a lot of its fine-tuning capacity. AdaMem leaves the input as it is and only modulates the existing computation, so the pretrained model needs far less change.
Freezing the action expert supports this. If I only train the new memory part, AdaMem still reaches 80% on picking up a bowl three times (compared to 88% when fine-tuning everything), while a concatenation-based variant fails almost completely (at most 4%).

Figure 3: The X-VLA-AdaMem variant is much more robust to freezing the action expert compared to the X-VLA-Concat variant.

So a small memory module and some fine-tuning are enough to turn a memory-less VLA into one that can keep track of how often it has done something, at least in simulation.

Limitations and Outlook

A few caveats apply. All experiments are in simulation, and each model is trained on a single task, so the learned memory is quite task-specific. The obvious next steps are testing on real robots, where noise and occlusions make the problem harder, and training on multiple tasks to see whether the memory generalizes.

The history is also limited to a fixed window of past frames. AdaMem struggles on very long tasks such as picking up a bowl 7 times, where 12 frames are simply too short, and just making the window longer gets expensive. Memory that keeps updating a running state instead of storing a window could handle much longer tasks.

Finally, the models only see perfect demonstrations during training, so a mistake in their own past could push them into situations they have never seen. Training on demonstrations that include failures and recoveries could make them more robust.
